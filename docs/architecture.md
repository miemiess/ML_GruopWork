# 架构与模块协作约定

版本：v1，2026-10-21。本文定义后续开发的目录、数据边界和依赖方向；配合[需求清单](requirements.md)执行。当前只有基础目录和说明，接口及运行命令仍待实现，不能据此声称系统已经可运行。

## 审阅结论

保留现有 Python 包、三个独立数据适配器、统一特征与模型的方向。采用一个进程内的模块化研究项目，不引入服务拆分或数据库。三个任务共享处理工具，各自保留数据协议、配置、模型与结果。

| 原有缺口 | 本次设定 | 解决的问题 |
| --- | --- | --- |
| 数据形状与元信息仅有口头约定 | `core/` 定义公共数据契约和配置校验 | 各数据适配器、窗口与模型可以对接 |
| 数据划分与评估职责混合 | 新增 `splitting/`，先划分原始记录 | 避免窗口泄漏及评估反向控制训练 |
| Notebook 容易各写一套完整流程 | 新增 `pipelines/` 作为统一编排入口 | 三个任务复用同一训练、验证与评估流程 |
| 缺少模型及预处理状态保存约定 | 新增 `artifacts/` 管理运行记录与模型文件 | 演示与复现实验使用同一套参数 |
| 测试目录没有对应分区 | 单元测试按模块分区，集成测试单独存放 | 组员可独立开发并验证边界 |
| 配置字段不足且示例不能运行 | 扩充规格模板，R02 实现严格校验 | 避免默认参数悄悄改变实验含义 |

## 分区与职责

以下是规划中的文件名，尚不存在的实现文件由对应需求创建。不要把任务专用实现复制到另一套目录。

| 模块 / 主要文件 | 唯一职责与产出 | 可以依赖 | 不承担的工作 |
| --- | --- | --- | --- |
| `core/contracts.py`、`core/config.py` | 数据结构、接口协议、配置校验、共享异常 | 标准库、NumPy | 读原始数据、训练模型 |
| `datasets/uci_gestures.py`、`putemg_force.py`、`zenodo_fatigue.py` | 检查源数据、解析并输出统一记录 | core、读取所需库 | 划分训练测试、标准化 |
| `splitting/grouped.py` | 按用户/会话划分记录，保存划分标识 | core、NumPy | 分窗、选特征、看测试指标选参数 |
| `preprocessing/windowing.py`、`transforms.py` | 按记录滤波、分窗、目标聚合、训练集拟合的变换 | core、NumPy/SciPy | 读取特定数据格式、实现模型 |
| `features/time_domain.py` | RMS、MAV、WL 等确定性窗口特征 | core、NumPy | 拟合标准化、训练模型 |
| `models/baselines.py`、`knn.py`、`logistic.py`、`ridge.py` | 自行实现模型训练、预测和状态导入导出 | core、NumPy | 文件读写、特征提取、评估选模 |
| `evaluation/metrics.py`、`comparisons.py`、`plots.py` | 从真实值和预测计算指标、对比及绘图 | core、NumPy、绘图库 | 修改模型或据测试结果选方案 |
| `artifacts/store.py` | 保存/读取配置、划分、环境、模型状态、结果 | core、标准库、NumPy | 重新训练、擅自重算预处理 |
| `pipelines/train.py`、`infer.py`、`__main__.py` | 按配置调用各模块，管理训练和推理顺序 | 上述模块 | 另写一套算法或数据解析 |
| `demo/` | 离线展示和使用说明，调用推理入口 | 已安装的 emginsight | 复制训练代码、自动重新拟合 |
| `notebooks/experiments/` | 数据探索、展示结果、记录结论 | 已安装的 emginsight | 成为唯一可运行实现 |

core 处于底层。普通模块不导入 pipelines、demo 或 Notebook。模块之间通过公共数据对象交换信息，不能读取别的模块的内部变量。模型与指标避免互相导入。任务名称只在适配器、配置和编排注册表出现，不在通用特征函数中编写数据集分支。

## 数据契约

统一约定：`T` 为单条记录的采样点数，`C` 为通道数，`W` 为单个窗口点数，`N` 为窗口数，`F` 为特征数，`O` 为回归输出数。

### Recording：适配器输出

一条对象对应一段连续、同用户、同会话的采集记录。建议字段如下，R01 落地为具名结构：

| 字段 | 类型 / 形状 | 必须满足 |
| --- | --- | --- |
| dataset_id、subject_id、session_id、recording_id | 字符串 | 记录标识在数据集内唯一；不同数据集不混用标识 |
| signal | 浮点数组 `(T, C)` | 与时间轴一致，不静默丢通道 |
| timestamps_s | 浮点数组 `(T,)` | 单位秒、严格递增；不规则采样不能冒充等间隔 |
| sampling_hz | 正数或待审计值 | 均匀采样须经验证；不规则记录须先说明重采样策略 |
| channel_names、signal_units | 长度 C 的列表 | 顺序固定，原始 ADC 值与物理单位区别明确 |
| target | 分类 `(T,)`；回归 `(T, O)`；推理可为 None | 训练/评估必须有目标；对齐至信号时间轴，保留目标名称、单位与标签映射 |
| valid_mask | 布尔数组 `(T,)` | 训练/评估标识信号与目标均有效的点；无标签推理只检查信号 |
| metadata | 可序列化字典 | 源文件相对路径、校验值、原始标签/时间单位、对齐与排除记录 |

适配器负责时间单位统一和目标时间对齐。疲劳评分原始时刻也要保留在来源记录中；插值/保持策略必须显式配置，不跨缺失区间外推。窗口模块只接收已经对齐的记录。

无效数据不默认变成 0。首版排除含无效点的窗口并统计数量；如新增插补方法，须单列需求并保证参数仅从训练集拟合。训练/评估中的分类窗口不能跨标签切换点；回归目标使用窗口内均值，其他聚合方法需在配置中明确并验证。

适配器区分训练/评估与无标签推理模式。推理不要求力量测量或类别列，不伪造目标；只依赖模型已记录的信号通道、采样与预处理规则。无标签推理按固定窗口处理，不执行需要真值的标签切换筛选，也不计算有监督指标。

### SplitAssignment：在分窗前生成

保存 `recording_id -> train / validation / test`、数据集版本、划分策略、种子及具体 subject/session IDs。未见用户实验中，同一用户的全部记录只能属于一个集合；会话留出实验使用 `(subject_id, session_id)` 组合键。不得把“留出会话”称为“未见用户”。

配置支持 load 读取已有划分，或 generate 按组与种子生成。generate 必须明确训练/验证/测试比例，三项为正且和为 1，保存实际组数、取整规则和生成文件；组数不足以产生非空集合时失败。load 校验文件与当前数据清单一致。正式比较使用同一份固定划分，不在每个模型运行时重抽。

若某类在训练集中不存在，停止该配置并报告；验证/测试缺类可继续，但必须保留完整类别列表并报告支持数。不能通过反复查看测试指标调整划分。

### WindowBatch 与 FeatureBatch

- WindowBatch：`signal: (N, W, C)`，分类 `y: (N,)` 或回归 `y: (N, O)`，无标签推理为 None；每个窗口附用户、会话、记录、起止时间。
- 一批窗口具有相同 W 与 C。不同采样率或通道组合分批处理，不能拼接不兼容数组。
- FeatureBatch：`X: (N, F)`，保留 y（推理可为 None）、全部分组信息和 `feature_names: (F,)`。训练入口必须拒绝缺失 y。
- 首版特征列按配置中的通道顺序排列，每通道按 `rms, mav, waveform_length` 排列，名称例如 `EMG_1:rms`。
- 通道 ID 在数据层解析成列索引，通用函数不猜测传入的是 0 起始还是 1 起始编号。
- 窗口数量为零、通道不存在、数据含无效值时，应返回可定位的错误或明确的排除统计。

### 模型与变换接口

规划中的模型实例方法：

```python
fit(X, y) -> self
predict(X) -> y_pred
get_state() -> dict
set_state(state) -> self
```

分类预测形状为 `(N,)`，保持既定整数标签映射；回归始终为 `(N, O)`，单输出也不自动压成一维。分类概率接口可选，若实现则注明类别顺序。不支持任务、未拟合、特征维度变化和非有限输入需报错。

标准化独立实现 `fit(X_train)`、`transform(X)` 和状态导入导出，不进入单个模型内部。零方差特征缩放因子设为 1。候选模型比较使用相同训练特征、验证划分和评价规则。

## 固定的数据流

```text
TOML 配置 + 来源清单
  -> datasets：读取与对齐 Recording
  -> splitting：按完整用户/会话划分原始记录
  -> preprocessing：各集合独立滤波与分窗
  -> features：确定性特征
  -> preprocessing：只在训练集 fit，验证/测试只 transform
  -> models：训练；仅用验证集选择模型/通道/超参数
  -> evaluation：方案固定后评估测试集
  -> artifacts：保存完整运行记录与可恢复状态
  -> pipelines.infer -> demo：复用已保存状态进行离线推理
```

每个验证折独立拟合标准化等变换。首版最终模型保留训练集拟合状态，不默认合并验证集重训；若采用重训，必须另存选择过程并明确训练数据范围。滤波不能跨记录或集合边界；任何窗口间重叠都限定在同一划分内。

## 配置与运行产物

`configs/experiment.example.toml` 是字段规格，不是可运行配置。正式配置按任务放入 `configs/gesture/`、`force/`、`fatigue/`。窗口、力目标单位和采样率在数据审计前不预设数值。

每次运行输出到 `results/runs/<run_id>/`，至少包含：

| 文件 | 内容 |
| --- | --- |
| `config.resolved.toml` | 本次实际生效的全部设置，不留隐式默认值 |
| `provenance.json`、`splits.json` | 数据校验值、排除规则及精确划分 |
| `environment.txt`、`run.json` | 依赖版本、Python/平台、Git 提交及工作区是否有修改、种子、命令、耗时 |
| `preprocessing.json`、`model.json`、`model.npz` | 特征顺序、预处理与模型状态、模式版本 |
| `metrics.json`、`predictions.csv` | 逐任务/类别/输出/用户的指标与预测索引 |
| `run.log` | 数据排除、警告、错误与运行状态 |

数组使用 NPZ，元信息使用 JSON；加载 NPZ 使用 `allow_pickle=False`。通过显式模型注册表恢复对象，不依据配置动态执行任意 Python 代码。保存后重新加载，预测应与保存前一致。预处理的数值状态也可放入单独 NPZ，并在 JSON 中引用。

运行目录保持本地；精简结果放入 `results/summaries/` 和 `results/figures/`。不要把原始参与者元信息放入公开结果。数据文件仍只存放在 `data/` 下。

## 测试与集成边界

`tests/unit/` 按模块分区；`tests/integration/` 使用合成数据验证跨模块完整流程；`tests/fixtures/` 仅放生成器或人工小样例；真实数据检查必须显式启用，默认测试不联网或下载数据。

每个需求的 PR 同时提交实现、相关测试、必要配置及接口说明。公共接口变更必须先更新本文并通知受影响任务的负责人。Notebook、demo 与报告不得改变核心算法行为。

架构可演进：由 Issue 说明动机、影响模块、迁移方式和验收方法，再通过 PR 同步变更。避免在个人分支上私自新增第二套数据类型或流程。

## 可并行开发的边界
